# Mini-Code Agent 提示词优化设计

**日期：** 2026-03-30
**状态：** 已批准
**目标：** 通过共享基础提示词和角色化专属提示词，提升 `coder`、`reviewer`、`researcher` 三类 agent 的工具稳定性、回答质量和角色分工清晰度。

---

## 1. 背景问题

当前实现存在两个主要问题：

1. 通用系统提示在 `pkg/agent/engine.go` 和 `pkg/orchestrator/orchestrator.go` 中重复维护，后续容易分叉。
2. 专化 agent 通过 `systemPromptOverride` 直接覆盖 system prompt，导致三类 agent 无法继承统一的基础行为规范。

这会让不同入口、不同 agent 的行为标准不一致，也会削弱提示词对工具顺序、输出风格和职责边界的约束力。

## 2. 设计目标

本次优化同时覆盖三类目标：

1. **工具使用更稳**：所有 agent 都遵守统一的基础规则，例如先理解项目、根据系统选择 shell 语法、最小修改、仅在必要时执行命令。
2. **回答质量更高**：明确要求结论基于代码库证据或工具结果，减少空泛建议。
3. **角色分工更清晰**：`coder` 专注实现，`reviewer` 专注审查，`researcher` 专注调研。

## 3. 方案概览

### 3.1 共享基础提示词

新增共享提示词构建逻辑，由同一个构建器负责输出：

- Mini-Code 身份和中文回复要求
- 运行环境和 shell 语法提示
- 先理解项目、再行动的基本流程
- 工具使用边界
- 代码质量和沟通规范
- 记忆后缀注入

`engine.go` 和 `orchestrator.go` 统一复用这一构建器，不再各自维护长文本。

### 3.2 角色化专属提示词

在共享基础提示词上追加角色专属规则，而不是整体覆盖：

- `coder`
  - 强调先读后改、最小修改、联动修复相似模式
  - 调试时优先在代码中添加日志
  - 默认不主动执行 lint、build、commit
- `reviewer`
  - 输出以 findings 为先
  - 优先关注 bug、回归风险、安全性和测试缺口
  - 只审查不修改
- `researcher`
  - 区分已验证事实与基于证据的推断
  - 输出推荐方案和对当前仓库的影响
  - 只在信息充分时写入记忆

### 3.3 组合方式

`BaseAgent.Run()` 不再直接以专属提示词替换 system prompt，而是：

1. 保留调用方传入的基础 system prompt
2. 若当前 agent 有专属角色提示，则将其附加到基础 system prompt 末尾

这样可以保证所有 agent 共享同一套底层行为规则，同时保留鲜明的角色差异。

## 4. 变更范围

- 新增共享提示词构建逻辑
- 更新 `BaseAgent` 的 system prompt 组合方式
- 更新 `coder` / `reviewer` / `researcher` 的角色提示词
- 删除重复的通用提示词实现
- 增加针对提示词结构和角色规则的测试

## 5. 测试策略

重点覆盖以下回归场景：

1. 基础提示词仍包含中文回复、项目理解和 shell 提示。
2. 专化 agent 运行时不会丢失基础提示词内容。
3. 三类 agent 的角色提示词包含关键约束。
4. `orchestrator` 与 `engine` 使用同一套基础提示词来源。
5. 现有工具权限测试继续通过，防止角色能力边界回退。
